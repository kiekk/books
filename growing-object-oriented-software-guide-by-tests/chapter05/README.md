## 5장 테스트 주도 개발 주기의 유지

### 5.3 테스트를 가장 간단한 성공 케이스로 시작하라

```markdown
새 클래스나 기능을 만들어야 할 때 어디서 출발해야 할까? 이 경우 쉽다는 이유로 상투적인 케이스나 실패 케이스로 시작하려는 생각이 들기 쉽다.
이를 두고 XP의 격언 중 하나인 "동작 가능한 가장 간단한 것"을 하는 것이라고 흔히 해석하는데 여기서 '간단한'을 '지나치게 단순화한'으로 해석해서는 안 된다.
...
해당 테스트가 동작하면 솔루션의 실제 구조에 관해 더 좋은 생각이 떠오를 테고, 그 과정에서 발견한 발생 가능한 실패를 처리하는 것과 이후의 성공 케이스 사이에서 우선순위를 가늠해볼 수 있다.
```

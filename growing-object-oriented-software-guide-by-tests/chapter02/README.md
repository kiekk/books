## 2장 객체를 활용한 테스트 주도 개발

### 2.1 객체망

```markdown
객체 지향 설계는 객체 자체보다 객체 간의 의사소통에 더 집중한다.
...
객체는 메시지로 의사소통한다.
...
객체에는 자신이 이해할 수 있는 모든 유형의 메시지를 처리하는 메서드(method)가 있으며, 대부분 다른 객체와 의사소통을 조율하는 데 사용하는 내부 상태를 캡슐화한다.
```

### 2.5 그래도 가끔은 물어라

```markdown
질의 메서드를 추가하면 가장 적절한 객체에 행위가 자리 잡아 행위에 이해하기 쉬운 이름이 생기고 테스트하기가 쉬워진다.
아울러 (값과 달리) 객체에 관한 질의를 되도록 적게 쓰려고 하는데, 질의가 정보를 객체 바깥으로 '새어 나가게'해서 시스템을 약간 더 경직되게 만들 수 있기 때문이다.
적어도 단지 구현이 아니라 호출하는 객체의 의도를 서술하는 질의를 작성하려고 애써야 한다.
```
